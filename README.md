# Foobu — AI Indian Recipe Generator

Foobu (food + buddy) is a full-stack web app that turns whatever ingredients you have into an authentic Indian recipe, generated by an LLM. Save your favorites, browse by category, and see favorite counts via a relational JOIN query. Built as a focused project covering a specific set of AI-app, backend, frontend, SQL, and NoSQL fundamentals — no extra features, no unrelated dependencies.

## Mandatory Topics Covered
**AI App Eng:** LLM API integration · Prompt engineering · Structured outputs
**Backend & System Design:** HTTP status codes · Middleware · Problem modeling · RESTful endpoint design · Server-side error handling · System design basics
**Engineering Practices:** Environment variables & secrets management · Git workflow
**Frontend:** Async data fetching · Client-side routing · async/await · Closures · Event loop · Hoisting · Promises vs callbacks · Component composition · useEffect · useState
**NoSQL (Mongo):** CRUD operations · Schema modeling
**SQL (Postgres):** Relational schema design with PK/FK · SQL JOINs

## Setup

### 1. Clone and install
```bash
git clone <repo-url>
cd foobu

# Backend
cd backend
npm install

# Frontend
cd ../frontend
npm install
```

### 2. Configure environment variables
```bash
cd backend
cp .env.example .env
# then fill in:
# PORT, LLM_API_KEY, LLM_API_URL, MONGO_URI, POSTGRES_URL
```
`.env` is gitignored — never commit real secrets.

### 3. Set up PostgreSQL schema
```bash
psql "$POSTGRES_URL" -f backend/src/db/init.sql
```
This creates `users`, `categories`, and `favorites` tables with proper PK/FK constraints, and seeds category rows (Curries, Dal, Sabzi, Rice, Roti/Paratha, Chaat, Mithai).

### 4. Run the app
```bash
# Terminal 1 — backend
cd backend
npm run dev

# Terminal 2 — frontend
cd frontend
npm run dev
```
Open the printed local URL (typically `http://localhost:5173`).

## How to Use
1. On the home page, enter ingredients you have (e.g. `paneer, tomatoes, ginger`).
2. The app calls the LLM and generates a structured Indian recipe — title, region, spice level, ingredients, and steps.
3. Click **Save** to persist it to MongoDB.
4. Visit **My Recipes** to browse saved recipes, filterable by category.
5. Mark recipes as **Favorite** — this writes a relational record in PostgreSQL linking your user, the category, and the recipe.
6. Visit **Favorites** to see a category-wise favorite count, computed via a SQL JOIN across `users`, `favorites`, and `categories`.

## API Endpoints
| Method | Route | Purpose |
|--------|-------|---------|
| POST | `/api/recipes/generate` | Generate a recipe via LLM (not saved yet) |
| POST | `/api/recipes` | Save a generated recipe to MongoDB |
| GET | `/api/recipes` | List saved recipes (optional `?category=`) |
| GET | `/api/recipes/:id` | Get one saved recipe |
| DELETE | `/api/recipes/:id` | Delete a saved recipe |
| POST | `/api/favorites` | Mark a recipe as favorite (Postgres) |
| GET | `/api/favorites/summary` | JOIN-based favorite counts by category |

## Security Notes
- All secrets (LLM key, DB URIs) are read from environment variables only — never hardcoded.
- `.env`, `.env.*.local`, and `node_modules/` are gitignored at both `frontend/` and `backend/`.
- All outbound requests (to the LLM API) use HTTPS only.
- User-supplied input (ingredients, route params) is validated/sanitized server-side before use in prompts or queries.
- Errors are handled centrally via middleware and never leak internal stack traces or secrets to the client — only a safe, generic message plus the correct HTTP status code.
